Application Integration Guide

Add "Sign in with {{ org_name }}" to your web application

What you'll build

Add hardware-backed authentication to your web application using OpenID Connect. Users authenticate with their YubiKey via {{ org_name }}, and your app receives verified identity claims including proof of hardware verification.

Prerequisites

  • A registered OAuth application (create one here)
  • Your client_id and client_secret
  • A configured redirect URI (e.g., https://yourapp.com/auth/callback)

Configuration Reference

Setting Value
Discovery URL {{ provider_url }}/.well-known/openid-configuration
Issuer {{ provider_url }}
Authorization Endpoint {{ provider_url }}/oauth/authorize
Token Endpoint {{ provider_url }}/oauth/token
UserInfo Endpoint {{ provider_url }}/oauth/userinfo
JWKS Endpoint {{ provider_url }}/oauth/jwks
Signing Algorithm ES256 (ECDSA P-256)
Scopes openid email profile

Note: {{ org_name }} uses ES256 signing. Most libraries auto-detect this from the JWKS, but you may need to configure it explicitly if your library defaults to RS256.

Framework Examples

Ruby on Rails with OmniAuth

Install the gem:

# Gemfile
gem 'omniauth-openid-connect'

Configure the provider:

# config/initializers/omniauth.rb
Rails.application.config.middleware.use OmniAuth::Builder do
  provider :openid_connect,
    name: :vouch,
    issuer: '{{ provider_url }}',
    discovery: true,
    client_options: {
      identifier: ENV['VOUCH_CLIENT_ID'],
      secret: ENV['VOUCH_CLIENT_SECRET'],
      redirect_uri: 'https://yourapp.com/auth/vouch/callback'
    },
    scope: [:openid, :email, :profile]
end

Handle the callback:

# app/controllers/sessions_controller.rb
class SessionsController < ApplicationController
  def create
    auth = request.env['omniauth.auth']
    user = User.find_or_create_by(email: auth.info.email) do |u|
      u.name = auth.info.name
    end

    # Check hardware verification
    if auth.extra.raw_info.hardware_verified
      session[:user_id] = user.id
      redirect_to root_path, notice: 'Signed in with hardware key!'
    else
      redirect_to root_path, alert: 'Hardware verification required'
    end
  end
end

# auth.py
from mozilla_django_oidc.auth import OIDCAuthenticationBackend

class VouchAuthBackend(OIDCAuthenticationBackend):
    def verify_claims(self, claims):
        verified = super().verify_claims(claims)
        # Require hardware verification
        return verified and claims.get('hardware_verified', False)

    def create_user(self, claims):
        user = super().create_user(claims)
        user.email = claims.get('email', '')
        user.first_name = claims.get('given_name', '')
        user.last_name = claims.get('family_name', '')
        user.save()
        return user

Express.js with Passport

Install dependencies:

npm install passport passport-openidconnect express-session

Configure Passport:

// app.js
const passport = require('passport');
const OpenIDConnectStrategy = require('passport-openidconnect');

passport.use('vouch', new OpenIDConnectStrategy({
  issuer: '{{ provider_url }}',
  authorizationURL: '{{ provider_url }}/oauth/authorize',
  tokenURL: '{{ provider_url }}/oauth/token',
  userInfoURL: '{{ provider_url }}/oauth/userinfo',
  clientID: process.env.VOUCH_CLIENT_ID,
  clientSecret: process.env.VOUCH_CLIENT_SECRET,
  callbackURL: '/auth/vouch/callback',
  scope: ['openid', 'email', 'profile']
}, (issuer, profile, context, idToken, accessToken, refreshToken, done) => {
  // profile contains user info, idToken has hardware_verified claim
  return done(null, {
    id: profile.id,
    email: profile.emails?.[0]?.value,
    name: profile.displayName,
    hardwareVerified: idToken.hardware_verified
  });
}));

passport.serializeUser((user, done) => done(null, user));
passport.deserializeUser((user, done) => done(null, user));

Add routes:

// routes.js
app.get('/auth/vouch', passport.authenticate('vouch'));

app.get('/auth/vouch/callback',
  passport.authenticate('vouch', { failureRedirect: '/login' }),
  (req, res) => {
    // Check hardware verification for sensitive actions
    if (!req.user.hardwareVerified) {
      return res.redirect('/login?error=hardware_required');
    }
    res.redirect('/');
  }
);

app.get('/logout', (req, res) => {
  req.logout(() => res.redirect('/'));
});

Next.js with NextAuth.js

Install NextAuth:

npm install next-auth

Configure the provider:

// pages/api/auth/[...nextauth].js (Pages Router)
// or app/api/auth/[...nextauth]/route.js (App Router)
import NextAuth from 'next-auth';

export default NextAuth({
  providers: [{
    id: 'vouch',
    name: 'Vouch',
    type: 'oauth',
    wellKnown: '{{ provider_url }}/.well-known/openid-configuration',
    clientId: process.env.VOUCH_CLIENT_ID,
    clientSecret: process.env.VOUCH_CLIENT_SECRET,
    authorization: { params: { scope: 'openid email profile' } },
    idToken: true,
    profile(profile) {
      return {
        id: profile.sub,
        email: profile.email,
        name: profile.name,
        image: profile.picture,
        hardwareVerified: profile.hardware_verified,
        hardwareAaguid: profile.hardware_aaguid
      };
    }
  }],
  callbacks: {
    async jwt({ token, profile }) {
      if (profile) {
        token.hardwareVerified = profile.hardware_verified;
        token.hardwareAaguid = profile.hardware_aaguid;
      }
      return token;
    },
    async session({ session, token }) {
      session.user.hardwareVerified = token.hardwareVerified;
      session.user.hardwareAaguid = token.hardwareAaguid;
      return session;
    }
  }
});

Use in a component:

// components/LoginButton.jsx
import { signIn, signOut, useSession } from 'next-auth/react';

export default function LoginButton() {
  const { data: session } = useSession();

  if (session) {
    return (
      <div>
        <p>Signed in as {session.user.email}</p>
        {session.user.hardwareVerified && (
          <span className="badge">Hardware Verified</span>
        )}
        <button onClick={() => signOut()}>Sign out</button>
      </div>
    );
  }

  return <button onClick={() => signIn('vouch')}>Sign in with Vouch</button>;
}

Laravel with Socialite

Install the package:

composer require socialiteproviders/openid-connect

Configure services:

// config/services.php
'vouch' => [
    'base_url' => '{{ provider_url }}',
    'client_id' => env('VOUCH_CLIENT_ID'),
    'client_secret' => env('VOUCH_CLIENT_SECRET'),
    'redirect' => env('VOUCH_REDIRECT_URI'),
],

Register the provider:

// app/Providers/EventServiceProvider.php
protected $listen = [
    \SocialiteProviders\Manager\SocialiteWasCalled::class => [
        \SocialiteProviders\OpenIDConnect\OpenIDConnectExtendSocialite::class.'@handle',
    ],
];

Controller implementation:

// app/Http/Controllers/AuthController.php
use Laravel\Socialite\Facades\Socialite;

class AuthController extends Controller
{
    public function redirect()
    {
        return Socialite::driver('openid-connect')
            ->setConfig(new \SocialiteProviders\Manager\Config(
                config('services.vouch.client_id'),
                config('services.vouch.client_secret'),
                config('services.vouch.redirect'),
                ['base_url' => config('services.vouch.base_url')]
            ))
            ->scopes(['openid', 'email', 'profile'])
            ->redirect();
    }

    public function callback()
    {
        $vouchUser = Socialite::driver('openid-connect')->user();

        $user = User::updateOrCreate(
            ['email' => $vouchUser->email],
            ['name' => $vouchUser->name]
        );

        // Store hardware verification status
        session(['hardware_verified' => $vouchUser->user['hardware_verified'] ?? false]);

        Auth::login($user);
        return redirect('/dashboard');
    }
}

// SecurityConfig.java
@Configuration

public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/", "/login").permitAll()
                .anyRequest().authenticated()
            )
            .oauth2Login(oauth2 -> oauth2
                .defaultSuccessUrl("/dashboard", true)
            );
        return http.build();
    }
}

Access user info in a controller:

// DashboardController.java
@Controller
public class DashboardController {

    @GetMapping("/dashboard")
    public String dashboard(@AuthenticationPrincipal OidcUser user, Model model) {
        model.addAttribute("email", user.getEmail());
        model.addAttribute("name", user.getFullName());

        // Access custom claims
        Boolean hardwareVerified = user.getClaim("hardware_verified");
        model.addAttribute("hardwareVerified", hardwareVerified);

        return "dashboard";
    }
}

use openidconnect::{
    core::{CoreClient, CoreProviderMetadata},
    ClientId, ClientSecret, IssuerUrl, RedirectUrl,

async fn create_oidc_client() -> Result> {
    let issuer_url = IssuerUrl::new("{{ provider_url }}".to_string())?;

    let provider_metadata = CoreProviderMetadata::discover_async(
        issuer_url,
        openidconnect::reqwest::async_http_client,
    ).await?;

    let client = CoreClient::from_provider_metadata(
        provider_metadata,
        ClientId::new(std::env::var("VOUCH_CLIENT_ID")?),
        Some(ClientSecret::new(std::env::var("VOUCH_CLIENT_SECRET")?)),
    )
    .set_redirect_uri(RedirectUrl::new("https://yourapp.com/callback".to_string())?);

    Ok(client)
}

Vouch-Specific Claims

In addition to standard OIDC claims, {{ org_name }} includes hardware verification information:

Claim Type Description
hardware_verified boolean Whether the user authenticated with a hardware security key
hardware_aaguid string The AAGUID of the authenticator (identifies the hardware model)

Security tip: For sensitive operations (admin actions, financial transactions), verify that hardware_verified is true before proceeding.

Service-to-Service (M2M) Authentication

For backend services that need to call other services on behalf of a user, use the Token Exchange flow (RFC 8693). This exchanges a user's access token for a new token scoped to a specific service.

When to use: Your backend receives a user's access token and needs to call another internal API while preserving the user's identity and permissions. 

# token_exchange.py
import requests
import os

def exchange_token(user_access_token: str, target_audience: str) -> str:
    """Exchange a user's access token for a service-scoped token."""

    response = requests.post(
        '{{ provider_url }}/oauth/token',
        auth=(os.environ['VOUCH_CLIENT_ID'], os.environ['VOUCH_CLIENT_SECRET']),
        data={
            'grant_type': 'urn:ietf:params:oauth:grant-type:token-exchange',
            'subject_token': user_access_token,
            'subject_token_type': 'urn:ietf:params:oauth:token-type:access_token',
            'audience': target_audience,
            'scope': 'read:data'  # optional: request specific scopes
        }
    )
    response.raise_for_status()
    return response.json()['access_token']

# Usage
user_token = request.headers.get('Authorization').replace('Bearer ', '')
service_token = exchange_token(user_token, 'https://api.internal.example.com')

# Call internal API with the new token
response = requests.get(
    'https://api.internal.example.com/data',
    headers={'Authorization': f'Bearer {service_token}'}
)
// tokenExchange.js

async function exchangeToken(userAccessToken, targetAudience) {
  const credentials = Buffer.from(
    `${process.env.VOUCH_CLIENT_ID}:${process.env.VOUCH_CLIENT_SECRET}`
  ).toString('base64');

  const response = await fetch('{{ provider_url }}/oauth/token', {
    method: 'POST',
    headers: {
      'Authorization': `Basic ${credentials}`,
      'Content-Type': 'application/x-www-form-urlencoded'
    },
    body: new URLSearchParams({
      grant_type: 'urn:ietf:params:oauth:grant-type:token-exchange',
      subject_token: userAccessToken,
      subject_token_type: 'urn:ietf:params:oauth:token-type:access_token',
      audience: targetAudience
    })
  });

  if (!response.ok) {
    throw new Error(`Token exchange failed: ${response.statusText}`);
  }

  const data = await response.json();
  return data.access_token;
}

// Usage in an Express route
app.get('/api/aggregate', async (req, res) => {
  const userToken = req.headers.authorization?.replace('Bearer ', '');

  const serviceToken = await exchangeToken(
    userToken,
    'https://api.internal.example.com'
  );

  const data = await fetch('https://api.internal.example.com/data', {
    headers: { 'Authorization': `Bearer ${serviceToken}` }
  }).then(r => r.json());

  res.json(data);
});
// token_exchange.rs
use reqwest::Client;
use serde::Deserialize;

#[derive(Deserialize)]
struct TokenResponse {
    access_token: String,
    token_type: String,
    expires_in: u64,
}

async fn exchange_token(
    client: &Client,
    user_access_token: &str,
    target_audience: &str,
) -> Result {
    let client_id = std::env::var("VOUCH_CLIENT_ID").unwrap();
    let client_secret = std::env::var("VOUCH_CLIENT_SECRET").unwrap();

    let response: TokenResponse = client
        .post("{{ provider_url }}/oauth/token")
        .basic_auth(&client_id, Some(&client_secret))
        .form(&[
            ("grant_type", "urn:ietf:params:oauth:grant-type:token-exchange"),
            ("subject_token", user_access_token),
            ("subject_token_type", "urn:ietf:params:oauth:token-type:access_token"),
            ("audience", target_audience),
        ])
        .send()
        .await?
        .json()
        .await?;

    Ok(response.access_token)
}

// Usage in an Axum handler
async fn aggregate_data(
    Extension(http_client): Extension,
    headers: HeaderMap,
) -> impl IntoResponse {
    let user_token = headers
        .get("Authorization")
        .and_then(|v| v.to_str().ok())
        .map(|s| s.trim_start_matches("Bearer "))
        .unwrap();

    let service_token = exchange_token(
        &http_client,
        user_token,
        "https://api.internal.example.com",
    ).await?;

    // Call internal API with the exchanged token
    let data: serde_json::Value = http_client
        .get("https://api.internal.example.com/data")
        .bearer_auth(&service_token)
        .send()
        .await?
        .json()
        .await?;

    Json(data)
}

Troubleshooting

ES256 algorithm not supported
Some libraries default to RS256. Configure your library to use ES256 explicitly, or ensure it reads the algorithm from the JWKS endpoint.
No refresh token received
{{ org_name }} does not issue refresh tokens. Sessions last 8 hours. After expiration, users must re-authenticate with their hardware key.
CORS errors in browser
For single-page applications (SPAs), register your application as type "spa" (public client) and ensure your origin is in the allowed redirect URIs.
Invalid redirect_uri
The redirect URI must exactly match one registered in your application settings, including the protocol (https) and any trailing slashes.
Token signature verification failed
Ensure your library fetches the JWKS from {{ provider_url }}/oauth/jwks and matches the kid in the token header.

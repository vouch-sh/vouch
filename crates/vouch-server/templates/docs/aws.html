AWS Integration

Configure AWS IAM to trust {{ org_name }} as an OIDC identity provider

How it works

Vouch issues OIDC ID tokens signed with ES256 (P-256 ECDSA). AWS fetches the public key from the JWKS endpoint ({{ provider_url }}/oauth/jwks) to verify tokens. Users authenticate with their YubiKey and then use vouch credential aws to get temporary AWS credentials via AssumeRoleWithWebIdentity.

1 Create the OIDC Provider in AWS

Register {{ org_name }} as an OIDC identity provider in your AWS account. AWS automatically validates certificates from trusted CAs, so no thumbprint is required. 

aws iam create-open-id-connect-provider \
  --url "{{ provider_url }}" \
  --client-id-list "{{ provider_url }}"
AWSTemplateFormatVersion: '2010-09-09'
Description: '{{ org_name }} OIDC Provider'

Resources:
  VouchOIDCProvider:
    # https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/aws-resource-iam-oidcprovider.html
    Type: AWS::IAM::OIDCProvider
    Properties:
      Url: {{ provider_url }}
      ClientIdList:
        - {{ provider_url }}
      Tags:
        - Key: Name
          Value: {{ org_name }}-oidc-provider

Outputs:
  OIDCProviderArn:
    Description: ARN of the OIDC provider
    Value: !GetAtt VouchOIDCProvider.Arn
    Export:
      Name: VouchOIDCProviderArn

Deploy: aws cloudformation deploy --template-file vouch-oidc.yaml --stack-name vouch-oidc 

# vouch_oidc.tf
# https://registry.terraform.io/providers/hashicorp/aws/latest/docs/resources/iam_openid_connect_provider

resource "aws_iam_openid_connect_provider" "vouch" {
  url            = "{{ provider_url }}"
  client_id_list = ["{{ provider_url }}"]

  tags = {
    Name = "{{ rp_id }}-oidc-provider"
  }
}

output "oidc_provider_arn" {
  description = "ARN of the OIDC provider"
  value       = aws_iam_openid_connect_provider.vouch.arn
}

Apply: terraform apply

2 Create an IAM Role

Create an IAM role that trusts the OIDC provider and grants the permissions your users need. 

# First, create the trust policy
cat > trust-policy.json <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::ACCOUNT_ID:oidc-provider/{{ rp_id }}"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "{{ rp_id }}:aud": "{{ provider_url }}"
        }
      }
    }
  ]
}
EOF

# Create the role (replace ACCOUNT_ID)
aws iam create-role \
  --role-name VouchDeveloperRole \
  --assume-role-policy-document file://trust-policy.json

# Attach policies as needed
aws iam attach-role-policy \
  --role-name VouchDeveloperRole \
  --policy-arn arn:aws:iam::aws:policy/ReadOnlyAccess
AWSTemplateFormatVersion: '2010-09-09'
Description: '{{ org_name }} IAM Role for developers'

Parameters:
  OIDCProviderArn:
    Type: String
    Description: ARN of the OIDC provider (from step 1)
    # Or use: !ImportValue VouchOIDCProviderArn

Resources:
  VouchDeveloperRole:
    Type: AWS::IAM::Role
    Properties:
      RoleName: VouchDeveloperRole
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Federated: !Ref OIDCProviderArn
            Action: sts:AssumeRoleWithWebIdentity
            Condition:
              StringEquals:
                {{ rp_id }}:aud: {{ provider_url }}
      ManagedPolicyArns:
        - arn:aws:iam::aws:policy/ReadOnlyAccess
      Tags:
        - Key: Name
          Value: VouchDeveloperRole

Outputs:
  RoleArn:
    Description: ARN of the IAM role
    Value: !GetAtt VouchDeveloperRole.Arn
# vouch_role.tf

data "aws_caller_identity" "current" {}

resource "aws_iam_role" "vouch_developer" {
  name = "VouchDeveloperRole"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Effect = "Allow"
        Principal = {
          Federated = aws_iam_openid_connect_provider.vouch.arn
        }
        Action = "sts:AssumeRoleWithWebIdentity"
        Condition = {
          StringEquals = {
            "{{ rp_id }}:aud" = "{{ provider_url }}"
          }
        }
      }
    ]
  })

  tags = {
    Name = "VouchDeveloperRole"
  }
}

# Attach policies as needed
resource "aws_iam_role_policy_attachment" "readonly" {
  role       = aws_iam_role.vouch_developer.name
  policy_arn = "arn:aws:iam::aws:policy/ReadOnlyAccess"
}

output "role_arn" {
  description = "ARN of the IAM role"
  value       = aws_iam_role.vouch_developer.arn
}

Tip: Restrict access by email with a condition: 

"Condition": {
  "StringEquals": {
    "{{ rp_id }}:aud": "{{ provider_url }}",
    "{{ rp_id }}:sub": ["alice@example.com", "bob@example.com"]
  }
}
3 Configure the Vouch CLI

Set up the CLI to use AWS credentials with the role you created. 

# Set up AWS credential helper (one-time)
vouch setup aws --role arn:aws:iam::ACCOUNT_ID:role/VouchDeveloperRole

# This configures ~/.aws/config with a profile that uses vouch
4 Test the Integration 
# Log in with your YubiKey
vouch login

# Test AWS access
aws sts get-caller-identity --profile vouch

# You should see your assumed role identity

Troubleshooting

Access denied when assuming role
Check that the role's trust policy uses the correct audience ({{ provider_url }}) and that your email matches any sub conditions.
Token signature verification failed
Ensure AWS can reach {{ provider_url }}/oauth/jwks to fetch the signing key. The JWKS endpoint must be publicly accessible.
Certificate not trusted (self-signed or private CA)
If using a self-signed certificate or private CA, you must provide a thumbprint when creating the OIDC provider. Use --thumbprint-list with the SHA-1 fingerprint of the TLS certificate.

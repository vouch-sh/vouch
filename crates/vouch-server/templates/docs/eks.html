Amazon EKS

Authenticate to EKS clusters using AWS IAM and EKS Access Entries

How it works

EKS Access Entries let you grant Kubernetes permissions directly to IAM principals. Vouch issues temporary AWS credentials via vouch credential aws, then aws eks get-token converts those credentials into a Kubernetes bearer token. No custom OIDC configuration on the cluster is needed.

vouch login → vouch credential aws → aws eks get-token → kubectl

Prerequisites

  1. Vouch AWS profile configured — run vouch setup aws if you haven't already
  2. AWS CLI v2 installed — aws --version should show 2.x
  3. kubectl installed — kubectl version --client

Setup

Run the setup command to configure kubeconfig. The command auto-detects your Vouch AWS profile and fetches the cluster endpoint from AWS.

vouch setup eks --cluster <cluster-name> --region <region>

Options:

  • --cluster — EKS cluster name (required)
  • --region — AWS region (auto-detected from profile or environment if omitted)
  • --profile — AWS profile name (auto-detected vouch profile if omitted)
  • --kubeconfig — kubeconfig path (defaults to ~/.kube/config)

Usage

$ vouch login

$ kubectl config use-context <cluster-name>-vouch

$ kubectl get pods

Creating EKS Access Entries

An EKS Access Entry maps an IAM principal to Kubernetes RBAC permissions. Create one for the IAM role used by your Vouch AWS profile.

AWS CLI

aws eks create-access-entry \
  --cluster-name <cluster-name> \
  --principal-arn arn:aws:iam::ACCOUNT:role/ROLE \
  --type STANDARD

aws eks associate-access-policy \
  --cluster-name <cluster-name> \
  --principal-arn arn:aws:iam::ACCOUNT:role/ROLE \
  --policy-arn arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy \
  --access-scope type=cluster

Terraform

resource "aws_eks_access_entry" "vouch_user" {
  cluster_name  = aws_eks_cluster.main.name
  principal_arn = "arn:aws:iam::ACCOUNT:role/ROLE"
  type          = "STANDARD"
}

resource "aws_eks_access_policy_association" "vouch_user" {
  cluster_name  = aws_eks_cluster.main.name
  principal_arn = aws_eks_access_entry.vouch_user.principal_arn
  policy_arn    = "arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy"

  access_scope {
    type = "cluster"
  }
}

Available Access Policies

EKS provides managed access policies that map to standard Kubernetes RBAC roles:

Policy Kubernetes Equivalent
AmazonEKSClusterAdminPolicy cluster-admin
AmazonEKSAdminPolicy admin (namespace-scoped)
AmazonEKSEditPolicy edit (namespace-scoped)
AmazonEKSViewPolicy view (namespace-scoped)

Use type=namespace in access_scope to restrict to specific namespaces.

Custom RBAC (Optional)

For fine-grained permissions beyond the managed policies, you can create the access entry without an access policy and bind it to a custom Kubernetes Role or ClusterRole. 

apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: vouch-developers
subjects:
- kind: Group
  name: arn:aws:iam::ACCOUNT:role/ROLE
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: ClusterRole
  name: edit
  apiGroup: rbac.authorization.k8s.io

AWS CodeArtifact

Use private npm, pip, and Maven packages with hardware-verified auth

How it works

AWS CodeArtifact hosts private packages for npm, pip, Maven, NuGet, Swift, Cargo, and generic formats. Authentication requires an STS token, which aws codeartifact login converts into a bearer token for your package manager. Vouch's credential_process provides the STS credentials automatically — every token request is backed by a YubiKey tap.

vouch login → credential_process → STS → codeartifact login → bearer token → package manager

Prerequisites

  • Vouch AWS profile configured — see the AWS setup guide
  • IAM role with codeartifact:GetAuthorizationToken and sts:GetServiceBearerToken permissions
1 Authenticate to CodeArtifact

Use aws codeartifact login with your Vouch profile. This fetches an authorization token and configures your package manager automatically. 

# Configure npm to use your CodeArtifact repository
aws codeartifact login \
  --tool npm \
  --domain my-domain \
  --domain-owner 123456789012 \
  --repository my-repo \
  --profile vouch

# npm is now configured — install packages as normal
npm install @my-scope/my-package
# Configure pip to use your CodeArtifact repository
aws codeartifact login \
  --tool pip \
  --domain my-domain \
  --domain-owner 123456789012 \
  --repository my-repo \
  --profile vouch

# pip is now configured — install packages as normal
pip install my-private-package

# For publishing, use twine
aws codeartifact login \
  --tool twine \
  --domain my-domain \
  --domain-owner 123456789012 \
  --repository my-repo \
  --profile vouch

twine upload --repository codeartifact dist/*
# Get an auth token for Maven
export CODEARTIFACT_AUTH_TOKEN=$(aws codeartifact \
  get-authorization-token \
  --domain my-domain \
  --domain-owner 123456789012 \
  --query authorizationToken \
  --output text \
  --profile vouch)

# Use the token in your settings.xml or pass via CLI
mvn deploy -s settings.xml

settings.xml — reference the environment variable as the password: 

<server>
  <id>codeartifact</id>
  <username>aws</username>
  <password>${env.CODEARTIFACT_AUTH_TOKEN}</password>
</server>

Token lifetime and refresh

CodeArtifact authorization tokens are valid for up to 12 hours by default. When the token expires, re-run aws codeartifact login to get a fresh token. If your Vouch session (8 hours) has also expired, run vouch login first.

2 Cross-Account Access

If your CodeArtifact domain is in a different AWS account, configure a separate Vouch profile with a role in that account and pass --profile to aws codeartifact login. 

# Set up a second profile for the artifacts account
vouch setup aws \
  --role arn:aws:iam::ARTIFACTS_ACCOUNT:role/CodeArtifactReader \
  --profile vouch-artifacts

# Use it when logging in to CodeArtifact
aws codeartifact login \
  --tool npm \
  --domain shared-packages \
  --domain-owner ARTIFACTS_ACCOUNT \
  --repository npm-store \
  --profile vouch-artifacts

Troubleshooting

Token expired during long build
Re-run aws codeartifact login to refresh the token. You can set a longer duration with --duration-seconds 43200 (12 hours max).
AccessDeniedException on login
Your IAM role needs codeartifact:GetAuthorizationToken and sts:GetServiceBearerToken permissions. Also ensure the CodeArtifact domain policy allows access from your account.
403 when installing packages
The IAM role also needs codeartifact:ReadFromRepository (or codeartifact:PublishPackageVersion for publishing). Check the repository resource policy.

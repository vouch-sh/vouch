Kubernetes Integration

Configure Kubernetes clusters to trust {{ org_name }} as an OIDC identity provider

How it works

Vouch issues OIDC ID tokens signed with ES256 (P-256 ECDSA). The Kubernetes API server fetches the public key from the JWKS endpoint ({{ provider_url }}/oauth/jwks) to verify tokens. Users authenticate with their YubiKey, then kubectl calls vouch credential k8s as an exec credential plugin to obtain tokens on demand.

1 Configure Kubernetes Cluster OIDC

The Kubernetes API server must be configured to trust {{ org_name }} as an OIDC identity provider. Configuration varies by cluster type.

Add these flags to the kube-apiserver configuration: 

--oidc-issuer-url={{ provider_url }}
--oidc-client-id=my-cluster
--oidc-username-claim=email
--oidc-username-prefix=-

Note: The --oidc-client-id value becomes the "audience" in your kubeconfig. You can use any identifier (typically the cluster name).

Use OIDC identity provider association: 

aws eks associate-identity-provider-config \
  --cluster-name my-cluster \
  --oidc \
  --identity-provider-config-name vouch \
  --identity-provider-config "issuerUrl={{ provider_url }},clientId=my-cluster,usernameClaim=email,usernamePrefix=-"

Note: EKS OIDC association may take a few minutes to become active. Replace my-cluster with your actual cluster name.

Use GKE Identity Service (requires GKE Enterprise or Anthos): 

# Enable Identity Service on the cluster
gcloud container clusters update my-cluster \
  --enable-identity-service

# Configure the OIDC provider
kubectl apply -f - <<EOF
apiVersion: authentication.gke.io/v2alpha1
kind: ClientConfig
metadata:
  name: vouch
  namespace: kube-public
spec:
  authentication:
  - name: vouch
    oidc:
      clientID: my-cluster
      issuerURI: {{ provider_url }}
      userClaim: email
      userPrefix: "-"
EOF

AKS requires Entra ID (Azure AD) integration or custom webhook authentication. For external OIDC providers, you can use AKS OIDC issuer with a webhook authenticator.

AKS native support for external OIDC providers is limited. Consider using a webhook token authenticator or alternative authentication methods.

2 Configure kubectl

Run the setup command to configure kubectl to use Vouch for authentication. 

# Interactive setup (lists available clusters)
vouch setup k8s --configure

# Or specify the cluster directly
vouch setup k8s --cluster my-cluster --configure

What this creates:

  • A new user vouch-{cluster} with exec credential plugin
  • A new context {cluster}-vouch using the Vouch user

Or manually add to your kubeconfig: 

# ~/.kube/config
users:
- name: vouch-my-cluster
  user:
    exec:
      apiVersion: client.authentication.k8s.io/v1
      command: vouch
      args:
        - credential
        - k8s
        - --audience
        - my-cluster
      interactiveMode: Never

contexts:
- name: my-cluster-vouch
  context:
    cluster: my-cluster
    user: vouch-my-cluster
3 Configure RBAC

Grant users access via Kubernetes RBAC. The username will be the user's email address from the Vouch token. 

apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: vouch-user-binding
  namespace: default
subjects:
- kind: User
  name: user@example.com  # Email from Vouch token
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: developer
  apiGroup: rbac.authorization.k8s.io
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: vouch-admin-binding
subjects:
- kind: User
  name: admin@example.com  # Email from Vouch token
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: ClusterRole
  name: cluster-admin
  apiGroup: rbac.authorization.k8s.io

Tip: Use a Group subject with email domain patterns to grant access to all users from your organization.

4 Test the Integration 
# Log in with your YubiKey
vouch login

# Switch to the Vouch context
kubectl config use-context my-cluster-vouch

# Test access
kubectl get pods

# Verify your identity
kubectl auth whoami

Token Claims

The OIDC ID token includes these claims that can be used for authorization: 

{
  "iss": "{{ provider_url }}",
  "sub": "user@example.com",
  "aud": "my-cluster",
  "email": "user@example.com",
  "email_verified": true,
  "hardware_verified": true,
  "hardware_aaguid": "2fc0579f-8113-47ea-b116-bb5a8db9202a",
  "exp": 1706700000,
  "iat": 1706671200
}

The hardware_verified and hardware_aaguid claims can be used for audit logging to verify that authentication was performed with a YubiKey.

Troubleshooting

Error: Unauthorized
Check that RBAC is configured for your email address and that the token hasn't expired. Run vouch login to refresh your session.
Error: Unable to connect to the server
Verify that your kubeconfig context points to the correct cluster and that the cluster is accessible from your network.
Token signature verification failed
Ensure the Kubernetes API server can reach {{ provider_url }}/oauth/jwks to fetch the signing key. The JWKS endpoint must be publicly accessible.
Audience mismatch
The --audience value in your kubeconfig must match the --oidc-client-id configured on the Kubernetes API server.

Cargo Integration

Authenticate to private Cargo registries using {{ org_name }}

How it works

{{ org_name }} implements Cargo's credential provider protocol (RFC 2730/3139) to authenticate with private Cargo registries. When you run cargo publish, cargo build, or other commands that need registry authentication, Cargo automatically invokes the Vouch credential provider to obtain a token.

Token management: Tokens are derived from your Vouch session and cached by Cargo based on the JWT expiration. No need to manually manage or rotate registry tokens.

Prerequisites

  • Vouch CLI installed and enrolled (vouch enroll)
  • Cargo installed (comes with rustup)
  • Private Cargo registry that accepts Bearer token authentication
1 Configure Cargo Credential Provider

Run the setup command to configure Cargo to use Vouch for authentication. 

# Show configuration instructions
vouch setup cargo

# Automatically configure Cargo (global provider)
vouch setup cargo --configure

# Configure for a specific registry only
vouch setup cargo --registry my-private-registry --configure

This adds the following to your ~/.cargo/config.toml: 

# Global credential provider (all registries)
[registry]
global-credential-providers = ["/path/to/vouch", "credential", "cargo", "--"]

# Or for a specific registry
[registries.my-private-registry]
credential-provider = ["/path/to/vouch", "credential", "cargo", "--"]
2 Authenticate with Your YubiKey

Log in with your YubiKey to start a session. 

vouch login
3 Use Cargo Normally

Cargo commands that require registry authentication will automatically use Vouch. 

# Build with dependencies from private registry
cargo build

# Publish to a private registry
cargo publish --registry my-private-registry

# Add a dependency from a private registry
cargo add my-crate --registry my-private-registry

Private Registry Configuration

To use a private registry, you need to configure its URL in ~/.cargo/config.toml: 

[registries.my-private-registry]
index = "sparse+https://registry.example.com/index/"
credential-provider = ["/path/to/vouch", "credential", "cargo", "--"]

For more information on private registries, see the Cargo Registries documentation.

Troubleshooting

"not authenticated" error
Make sure you're logged in with vouch login. Sessions expire after 8 hours.
Cargo not using Vouch
Verify the credential provider is configured with cat ~/.cargo/config.toml | grep -A2 credential. Make sure the path to the vouch binary is correct.
"unsupported protocol version" error
You may have an older version of Cargo. The credential provider protocol requires Cargo 1.74 or later. Update with rustup update.
Token not being cached
Cargo caches tokens based on the expiration time from the JWT. If caching isn't working, check your Vouch session status with vouch status.
Multiple credential providers configured
Cargo tries credential providers in order. If another provider is configured, it may be used instead of Vouch. Check ~/.cargo/config.toml for other providers.

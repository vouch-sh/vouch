SCIM Provisioning

Automate user lifecycle management with your identity provider

How it works

{{ org_name }} supports SCIM 2.0 (System for Cross-domain Identity Management) for automated user provisioning. When you connect your identity provider (Okta, Azure AD, etc.), user accounts are automatically created when employees join, updated when their information changes, and immediately deactivated when they leave—revoking all active sessions and SSH certificates.

1 Generate a SCIM Token

Organization administrators can create SCIM tokens via the API. You must have an active session (authenticate with your YubiKey first). 

# Create a SCIM token (requires admin session)
# The SESSION_TOKEN comes from your browser cookie or vouch login
curl -X POST {{ provider_url }}/api/v1/org/scim-tokens \
  -H "Authorization: Bearer $SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"description": "Google Workspace SCIM"}'

# Response includes the token (shown only once):
# {
#   "id": "01234567-89ab-cdef-0123-456789abcdef",
#   "token": "vouch_scim_abc123...",
#   "description": "Google Workspace SCIM",
#   "created_at": "2024-01-15T10:30:00Z"
# }

Security note: SCIM tokens are hashed before storage. The plaintext token is only shown once at creation time and cannot be retrieved later. Tokens can optionally have an expiration date by adding "expires_in_days": 365 to the request.

2 Configure Your Identity Provider

Configure your identity provider to provision users via SCIM. Use the following settings:

SCIM Base URL
{{ provider_url }}/scim/v2
Authentication
Bearer Token (OAuth Bearer)
Token Header
Authorization: Bearer vouch_scim_<your-token>

4. Click Configure API Integration and check Enable API integration

6. Click Test API Credentials to verify the connection
7. Under To App, enable Create Users, Update User Attributes, and Deactivate Users

8. Expand Mappings and configure attribute mappings as needed

3 Test the Integration

Verify the SCIM connection is working by testing the endpoints directly. 

# Test the SCIM connection (replace with your token)
curl -H "Authorization: Bearer vouch_scim_YOUR_TOKEN" \
     {{ provider_url }}/scim/v2/ServiceProviderConfig

# List provisioned users
curl -H "Authorization: Bearer vouch_scim_YOUR_TOKEN" \
     {{ provider_url }}/scim/v2/Users

# List provisioned groups
curl -H "Authorization: Bearer vouch_scim_YOUR_TOKEN" \
     {{ provider_url }}/scim/v2/Groups

SCIM 2.0 Endpoints

Endpoint Methods Description
/scim/v2/ServiceProviderConfig GET Server capabilities and configuration
/scim/v2/Schemas GET Supported resource schemas
/scim/v2/ResourceTypes GET Available resource types
/scim/v2/Users GET, POST List users (with filtering) or create user
/scim/v2/Users/:id GET, PATCH, DELETE Get, update, or delete a specific user
/scim/v2/Groups GET, POST List groups (with filtering) or create group
/scim/v2/Groups/:id GET, PATCH, DELETE Get, update, or delete a specific group

Immediate De-provisioning

When a user is deactivated or deleted via SCIM, {{ org_name }} immediately:

  • Invalidates all active sessions for the user
  • Revokes all SSH certificates (they become untrusted immediately)
  • Prevents new logins and credential issuance
  • Logs the de-provisioning action for audit purposes

This ensures that when an employee leaves your organization, their access is revoked within seconds of the SCIM deactivation request.

Managing SCIM Tokens

# List all SCIM tokens for your organization
curl {{ provider_url }}/api/v1/org/scim-tokens \
  -H "Authorization: Bearer $SESSION_TOKEN"

# Create a token with expiration (365 days)
curl -X POST {{ provider_url }}/api/v1/org/scim-tokens \
  -H "Authorization: Bearer $SESSION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"description": "Azure AD", "expires_in_days": 365}'

# Revoke a token by ID
curl -X DELETE {{ provider_url }}/api/v1/org/scim-tokens/TOKEN_ID \
  -H "Authorization: Bearer $SESSION_TOKEN"

Troubleshooting

401 Unauthorized
Check that the Bearer token is correct and has not expired. Tokens must start with vouch_scim_. Verify the token hasn't been revoked by listing tokens via the API.
409 Conflict when creating user
A user with that email address already exists. SCIM uses email as the unique identifier (userName). If the user was manually enrolled, they already exist in the system.
Users not syncing
Check that your identity provider has provisioning enabled and the correct users/groups are assigned to the application. Review the provisioning logs in your IdP's admin console for specific errors.
Attribute mapping issues
{{ org_name }} requires userName (email address) as the primary identifier. Optional attributes include name.givenName, name.familyName, and externalId.

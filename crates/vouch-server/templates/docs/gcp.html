Google Cloud Integration

Configure GCP Workload Identity Federation to trust {{ org_name }} as an OIDC identity provider

How it works

Vouch issues OIDC ID tokens signed with ES256 (P-256 ECDSA). GCP fetches the public key from the JWKS endpoint ({{ provider_url }}/oauth/jwks) to verify tokens. Users authenticate with their YubiKey and then use vouch setup gcp to configure Workload Identity Federation for seamless credential access.

1 Create a Workload Identity Pool

Create a Workload Identity Pool to organize external identities. 

gcloud iam workload-identity-pools create vouch-pool \
  --location="global" \
  --display-name="Vouch Identity Pool" \
  --description="Workload identity pool for {{ org_name }}"
# vouch_identity_pool.tf
# https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/iam_workload_identity_pool

resource "google_iam_workload_identity_pool" "vouch" {
  workload_identity_pool_id = "vouch-pool"
  display_name              = "Vouch Identity Pool"
  description               = "Workload identity pool for {{ org_name }}"
}

output "pool_name" {
  value = google_iam_workload_identity_pool.vouch.name
}
2 Create an OIDC Provider in the pool

Add {{ org_name }} as an OIDC identity provider in the Workload Identity Pool. 

gcloud iam workload-identity-pools providers create-oidc vouch-provider \
  --location="global" \
  --workload-identity-pool="vouch-pool" \
  --issuer-uri="{{ provider_url }}" \
  --attribute-mapping="google.subject=assertion.sub,attribute.email=assertion.email,attribute.hardware_verified=assertion.hardware_verified,attribute.hd=assertion.hd"
# vouch_identity_provider.tf
# https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/iam_workload_identity_pool_provider

resource "google_iam_workload_identity_pool_provider" "vouch" {
  workload_identity_pool_id          = google_iam_workload_identity_pool.vouch.workload_identity_pool_id
  workload_identity_pool_provider_id = "vouch-provider"
  display_name                       = "Vouch OIDC Provider"

  oidc {
    issuer_uri = "{{ provider_url }}"
  }

  attribute_mapping = {
    "google.subject"              = "assertion.sub"
    "attribute.email"             = "assertion.email"
    "attribute.hardware_verified" = "assertion.hardware_verified"
    "attribute.hd"                = "assertion.hd"
  }
}

output "provider_name" {
  value = google_iam_workload_identity_pool_provider.vouch.name
}

Attribute Mapping: The hardware_verified claim allows you to create IAM conditions that require YubiKey authentication. The hd (hosted domain) claim allows filtering by Google Workspace domain.

Tip: Restrict access by Google Workspace domain with an attribute condition: 

--attribute-condition="assertion.hd == 'acme.com'"

The hd claim is only present for users who sign in with a Google Workspace account.

3 Grant Service Account Impersonation (Optional)

For most use cases, you'll want to impersonate a service account to get GCP credentials. Grant the Workload Identity User role to allow impersonation. 

# Allow a specific user to impersonate the service account
gcloud iam service-accounts add-iam-policy-binding \
  SA_EMAIL@PROJECT.iam.gserviceaccount.com \
  --role="roles/iam.workloadIdentityUser" \
  --member="principalSet://iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/vouch-pool/attribute.email/user@example.com"

# Or allow all users from {{ org_name }}
gcloud iam service-accounts add-iam-policy-binding \
  SA_EMAIL@PROJECT.iam.gserviceaccount.com \
  --role="roles/iam.workloadIdentityUser" \
  --member="principalSet://iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/vouch-pool/*"
# vouch_sa_binding.tf
# https://registry.terraform.io/providers/hashicorp/google/latest/docs/resources/google_service_account_iam

data "google_project" "current" {}

resource "google_service_account_iam_member" "vouch_impersonate" {
  service_account_id = google_service_account.my_sa.name
  role               = "roles/iam.workloadIdentityUser"
  member             = "principalSet://iam.googleapis.com/${google_iam_workload_identity_pool.vouch.name}/attribute.email/user@example.com"
}

# Or allow all users from the pool
resource "google_service_account_iam_member" "vouch_impersonate_all" {
  service_account_id = google_service_account.my_sa.name
  role               = "roles/iam.workloadIdentityUser"
  member             = "principalSet://iam.googleapis.com/${google_iam_workload_identity_pool.vouch.name}/*"
}

Tip: Add an IAM condition to require hardware verification: 

--condition='expression=request.auth.claims.hardware_verified == true,title=Require YubiKey'
4 Configure the Vouch CLI

Set up the CLI to use GCP credentials with Workload Identity Federation.

If your organization admin has configured GCP integration, setup is a single command: 

# Set up GCP credential helper (fetches config from server)
vouch setup gcp --configure

# Enable executable credential sources
gcloud config set auth/credential_source_command_override true

# Set the environment variable (add to your shell profile)
export GOOGLE_APPLICATION_CREDENTIALS=~/.config/gcloud/vouch-credentials.json

Profiles: Use --profile prod to create multiple credential files for different service accounts (e.g., prod vs staging).

Specify all configuration parameters manually: 

# Set up GCP credential helper (one-time)
vouch setup gcp \
  --project-number PROJECT_NUMBER \
  --pool-id vouch-pool \
  --provider-id vouch-provider \
  --service-account SA_EMAIL@PROJECT.iam.gserviceaccount.com \
  --configure

# Enable executable credential sources
gcloud config set auth/credential_source_command_override true

# Set the environment variable (add to your shell profile)
export GOOGLE_APPLICATION_CREDENTIALS=~/.config/gcloud/vouch-credentials.json

Power User Tip: Use direnv for per-directory credentials. Add to your project's .envrc: 

export GOOGLE_APPLICATION_CREDENTIALS=~/.config/gcloud/vouch-credentials-prod.json
5 Test the Integration 
# Log in with your YubiKey
vouch login

# Test GCP access
gcloud projects list

# Or use any GCP client library - they'll automatically
# use the credential helper

Troubleshooting

Permission denied when accessing GCP resources
Check that the service account has the necessary IAM permissions and that the Workload Identity User binding is correctly configured for your email address.
Token signature verification failed
Ensure GCP can reach {{ provider_url }}/oauth/jwks to fetch the signing key. The JWKS endpoint must be publicly accessible.
Executable credential source not working
Ensure you've run gcloud config set auth/credential_source_command_override true and that GOOGLE_APPLICATION_CREDENTIALS points to the correct file.
Invalid audience format error
The audience must be the full Workload Identity Pool provider resource name: //iam.googleapis.com/projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/POOL_ID/providers/PROVIDER_ID

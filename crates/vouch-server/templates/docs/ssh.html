SSH Certificates

Configure SSH servers to trust {{ org_name }} certificates for passwordless authentication

How it works

{{ org_name }} runs an SSH Certificate Authority (CA) using Ed25519. After authenticating with your YubiKey, you can request a short-lived SSH certificate that servers trust automatically. Certificates are valid for 8 hours (matching your session duration) and include your email and username as principals.

1 Set Up the CLI (For Developers)

Run the setup command to configure your SSH client. This downloads the CA public key and configures ~/.ssh/config to use certificates automatically. 

# One-time setup (downloads CA, configures SSH)
vouch setup ssh

# Log in with your YubiKey
vouch login

# Get a certificate (valid for 8 hours)
vouch credential ssh

After running these commands, ssh user@server will use your certificate automatically.

2 Configure SSH Servers (For Admins)

Configure your SSH servers to trust the {{ org_name }} CA. Users with valid certificates will be able to authenticate without adding individual public keys. 

# 1. Download CA public key from {{ org_name }}
curl -o /etc/ssh/vouch_ca.pub {{ provider_url }}/v1/credentials/ssh/ca

# 2. Configure sshd to trust the CA (using drop-in config)
# See: https://man.openbsd.org/sshd_config#TrustedUserCAKeys
cat > /etc/ssh/sshd_config.d/99-vouch-trustca.conf <<'EOF'
TrustedUserCAKeys /etc/ssh/vouch_ca.pub
EOF

# 3. Validate configuration and reload SSH daemon
sudo sshd -t && sudo systemctl reload sshd
---
# vouch_ssh_ca.yml
- name: Configure {{ org_name }} SSH CA
  hosts: all
  become: yes
  tasks:
    - name: Download {{ org_name }} CA public key
      ansible.builtin.get_url:
        url: "{{ provider_url }}/v1/credentials/ssh/ca"
        dest: /etc/ssh/vouch_ca.pub
        mode: '0644'

    - name: Trust {{ org_name }} CA for user certificates
      ansible.builtin.copy:
        dest: /etc/ssh/sshd_config.d/99-vouch-trustca.conf
        content: "TrustedUserCAKeys /etc/ssh/vouch_ca.pub\n"
        mode: '0644'
      notify: reload sshd

  handlers:
    - name: reload sshd
      ansible.builtin.systemd:
        name: sshd
        state: reloaded

Run: ansible-playbook -i inventory vouch_ssh_ca.yml 

# vouch_ssh_ca.tf - Example for AWS EC2 user data

variable "vouch_ca_url" {
  description = "URL to fetch {{ org_name }} SSH CA public key"
  default     = "{{ provider_url }}/v1/credentials/ssh/ca"
}

locals {
  ssh_ca_setup = <<-EOF
    #!/bin/bash
    # Download {{ org_name }} CA public key
    curl -o /etc/ssh/vouch_ca.pub ${var.vouch_ca_url}

    # Configure sshd to trust the CA
    echo "TrustedUserCAKeys /etc/ssh/vouch_ca.pub" > \
      /etc/ssh/sshd_config.d/99-vouch-trustca.conf

    # Reload SSH daemon
    systemctl reload sshd
  EOF
}

# Use in EC2 instance user_data
resource "aws_instance" "example" {
  # ... other configuration ...
  user_data = local.ssh_ca_setup
}

Tip: Certificates include two principals: the user's email (alice@example.com) and username (alice). Users can SSH as either principal if the server has a matching account.

3 Test the Connection 
# Make sure you're logged in
vouch login

# Get a fresh certificate
vouch credential ssh

# Connect to your server
ssh username@server.example.com

# Check certificate details (optional)
ssh-keygen -L -f ~/.ssh/id_vouch-cert.pub

How Certificate Authentication Works

1. You authenticate with your YubiKey via vouch login
2. vouch credential ssh generates a keypair and sends the public key to {{ org_name }}
3. {{ org_name }} signs the public key with the CA, creating a certificate with your identity
4. When you SSH, the server verifies the certificate signature against the trusted CA
5. The server checks that a principal in the certificate matches a valid username

IDE Remote Development

Because Vouch configures your local ~/.ssh/config, IDE remote development features that use your SSH config work automatically:

  • VS Code Remote - SSH — connect to remote hosts from the command palette
  • JetBrains Gateway — remote development via SSH
  • scp, rsync, sftp — any tool that reads SSH config

No additional configuration needed. Just run vouch login and your IDE picks up the certificate automatically.

Troubleshooting

Certificate expired
Certificates are valid for 8 hours. Run vouch credential ssh to get a new certificate. If your session has also expired, run vouch login first.
Server not accepting certificate
Verify the server has TrustedUserCAKeys configured and pointing to the correct CA public key. Check with: sudo sshd -T | grep trustedusercakeys
Permission denied (publickey)
The certificate's principals must match a valid username on the server. Your certificate includes your email and username as principals. Ensure a matching user account exists on the server.
Connection works with key but not certificate
SSH may be using your regular key instead of the certificate. Use verbose mode to debug: ssh -v user@server and look for "Offering public key" vs "Offering certificate".

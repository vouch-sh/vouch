SSM Session Manager

SSH to EC2 instances through Session Manager with hardware-verified access

How it works

AWS Systems Manager Session Manager provides shell access to EC2 instances without opening inbound ports or managing SSH keys. Sessions are tunneled through the SSM agent and authenticated via IAM. With Vouch's credential_process, every session start requires a hardware-verified identity, and STS session tags populate the SSM session with your email for audit.

Benefits over direct SSH

  • No security group changes — instances don't need port 22 open
  • No key management — authentication is through IAM, not SSH keys
  • Full audit trail — every session is logged in CloudTrail with your Vouch identity
  • Private instances — works with instances that have no public IP

Prerequisites

  • Vouch AWS profile configured — see the AWS setup guide
  • Session Manager plugin installed
  • EC2 instances with the SSM agent running and an instance profile with AmazonSSMManagedInstanceCore
1 Configure SSH ProxyCommand

Add a host pattern to ~/.ssh/config that routes connections to instance IDs through Session Manager. 

# ~/.ssh/config
Host i-*
    ProxyCommand sh -c "AWS_PROFILE=vouch aws ssm start-session --target %h --document-name AWS-StartSSHSession --parameters 'portNumber=%p'"
    User ec2-user
    StrictHostKeyChecking accept-new

This matches any hostname starting with i- (EC2 instance IDs) and tunnels through SSM.

2 Connect to an Instance

SSH to any instance by its instance ID. Vouch's credential_process handles FIDO2 verification automatically when the SSH connection triggers an AWS API call. 

# SSH via SSM — triggers FIDO2 verification
ssh i-0123456789abcdef0

# Or start a raw session (no SSH)
AWS_PROFILE=vouch aws ssm start-session --target i-0123456789abcdef0
3 Port Forwarding

Use SSM port forwarding to access databases and other services running on private instances without exposing them to the network. 

# Forward local port 5432 to RDS through a bastion instance
AWS_PROFILE=vouch aws ssm start-session \
  --target i-0123456789abcdef0 \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{
    "host": ["my-database.cluster-abc123.us-east-1.rds.amazonaws.com"],
    "portNumber": ["5432"],
    "localPortNumber": ["5432"]
  }'

# Then connect locally
psql -h localhost -p 5432 -U myuser mydb

Session identity and audit

Vouch passes your email and domain as STS session tags with every credential request. These tags appear in CloudTrail as part of the StartSession event, providing a clear audit trail from YubiKey tap to SSM session.

Troubleshooting

SessionManagerPlugin is not found
Install the Session Manager plugin. On macOS: brew install session-manager-plugin.
TargetNotConnected error
The SSM agent is not running or the instance doesn't have connectivity to the SSM endpoints. Verify the instance profile includes AmazonSSMManagedInstanceCore and the instance can reach SSM endpoints (via NAT, VPC endpoint, or public IP).
Access denied on StartSession
Your IAM role needs ssm:StartSession permission. You can scope this to specific instances using resource ARNs or tags.
